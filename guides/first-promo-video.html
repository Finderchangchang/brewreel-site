使用指南

用 BrewReel 做第一支宣传片：先跑样例，再换成自己的产品

从本地依赖到样例出片，再到产品简报与发布检查。把环境是否可用、模型是否写对和成片是否能发布分开验证。

Finderchangchang · 2026-10-06

先理解三件事分别由谁完成

你提供简报和素材；语言模型按项目的配方写分镜 JSON；BrewReel 使用本地渲染程序生成视频。先跑仓库已有样例，可以在接入模型之前确认渲染环境是否可用。

cards 配方适合卖点和流程讲解，quiz 适合答题揭晓，journey 适合角色漫游。cards、quiz 默认 1080×1920，journey 默认 1080×1350。配方的可用状态与参数以仓库说明为准。

准备本地环境

当前项目 README 列出 Node.js 18+、Python 3.10+；项目记录了 Node 22 环境测试。DeepSeek Harness 插件的运行要求另列，不能直接套用普通脚本的要求。还需要 Git、npm 以及依赖下载空间。Windows 按项目说明使用 x64 环境。

1. 安装渲染依赖

git clone https://github.com/Finderchangchang/brewreel.git
cd brewreel/template
npm install
npx remotion browser ensure
cd ..
python -m pip install numpy scipy imageio-ffmpeg

如果系统只提供 python3 命令，把最后一行改成 python3 -m pip install numpy scipy imageio-ffmpeg。以上命令依次安装渲染组件、下载无头浏览器、安装配乐依赖。浏览器下载失败时先检查网络和项目的本地浏览器配置说明，不要把它当作分镜问题。

口播配画面需要完整版 ffmpeg。Remotion 自带的是精简版，装 imageio-ffmpeg，或把完整版放进 PATH，或用环境变量 FFMPEG 指过去。

2. 校验并渲染仓库样例

node scripts/validate.mjs examples/ledger.json
node scripts/make.mjs examples/ledger.json --out ../brewreel-out/ledger

在 brewreel 仓库根目录执行。输出目录放在仓库外。静态校验通过只说明样例满足校验规则；还要让实际渲染完成，才能检查视频和交付文件。

按项目 README，输出包括 video.mp4、sheet.png、check/、report.txt 和 manifest.json。打开视频看完整片，查看检查报告，并核对清单中的分镜与本次任务一致。

3. 换成你的产品简报

把产品名、目标用户、核心动作、卖点、事实来源、素材和获取方式写清楚，再让模型按项目 SKILL 与所选行业配方生成分镜。可以从产品简报模板指南开始。没有的数据写「无」，不要让模型补出看似真实的效果数字。

生成分镜后重复「校验 → 渲染 → 看成片」，把报错和人工发现的问题反馈到分镜。模型调用与可选语音服务可能另收费。

4. 发布前逐项检查

  • 产品名、功能、价格和适用条件是否与简报一致。
  • 字幕是否能读清，旁白是否自然，音乐是否压过人声。
  • 实拍、截图和插画的来源与标注是否正确。
  • 片尾获取方式是否真实可用，有没有编造渠道。
  • 是否已按发布平台要求处理 AI 内容标识。

项目校验帮助发现部分问题，不能代替人工验片或正式业务审核。样片能渲染，不等于已经适合客户直接发布。

查看项目和依赖各自的许可

BrewReel 采用 Apache-2.0；再分发和二次开发需按项目 LICENSE、NOTICE 保留相应信息。渲染的视频不要求项目署名。Remotion 有独立许可，4 人及以上的营利组织需购买 Company License，详见官方许可。

这是按公开 README 编写的起步流程，本次网站更新没有重新渲染或评测样片。命令、已知限制和版本变化请核对 项目文档。
